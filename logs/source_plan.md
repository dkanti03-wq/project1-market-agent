## 2. 수집 우선순위 원칙 및 파이프라인

수집 안정성과 속도, 리소스 효율성을 위해 아래의 4단계 계층 전략을 적용합니다:

```
[1순위: RSS Feed] ──(표준화/고속)──> [2순위: requests + BS4] ──(정적 스크래핑)──>
[3순위: 공개 API] ──(정형 데이터)──> [4순위: Playwright] ──(동적 렌더링 필요 시)
                                      └───> [Fallback: 로컬 CSV (800건 보장)]
```

1. **1순위 (RSS)**: 차단 위험이 없고 주기적 업데이트가 보장되는 공개 RSS 피드 우선 활용
2. **2순위 (requests + BeautifulSoup)**: 공개 웹페이지/공고 목록의 HTML 파싱 및 본문 세부 스크래핑
3. **3순위 (공개 API)**: 별도 인증/키 제한이 적은 오픈 API 엔드포인트 활용
4. **4순위 (Playwright)**: JavaScript 동적 렌더링이 필수적인 공공 포털 및 대시보드 대응
5. **Fallback (로컬 데이터)**: 네트워크 단절 및 수집 부족(200건 미만) 시 `data/fallback/fallback_market_news.csv` (800건) 자동 병합

## 4. 수집량 시뮬레이션 및 200건 확보 가능성 평가

### 4.1 소스별 예상 수집량
- **실시간 공개 RSS (Google News 3개 채널)**: 약 220 ~ 280건
- **전문 테크/산업 매체 RSS (AI Times, 로봇신문)**: 약 100건
- **공개 공고/웹 스크래핑**: 약 30 ~ 50건
- **라이브 수집 총합**: **약 350 ~ 430건**

### 4.2 목표 수집량(최소 200건) 평가 결론
- **라이브 수집만으로도 200건 초과 달성 가능** (예상 350건+ 확보).
- 네트워크 불안정, IP Rate Limit 등의 예외 상황 발생 시에도 `data/fallback/fallback_market_news.csv`에 보관된 **800건의 검증된 데이터**를 즉시 활용할 수 있어, **200건 이상의 데이터 무결성 확보 확률은 100%**입니다.
